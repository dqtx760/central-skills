# Workflow Packaging Audit

本技能用于把用户最近反复做的工作，审计成可复用资产。目标不是多造技能，而是减少未来重复劳动。

## 核心原则

优先复用已有资产。只有证据足够、边界清楚、且现有技能/自动化不能充分覆盖时，才创建新内容。

保持资产小而窄：

- Skill：稳定输入、固定步骤、明确输出的可复用工作流。
- Custom subagent：适合委托的边界清楚的调查、验证或实现角色；如果当前环境没有可持久保存的自定义子代理机制，只提出建议，不伪造配置。
- Automation：定时检查、报告、提醒、监控；创建前先查现有自动化，能更新就更新。
- Skip：证据不足、太一次性、太敏感、边界不清、已有资产已覆盖。

## 证据顺序

按以下顺序收集证据：

1. 最近 30 天 Codex sessions / thread summaries；如果历史少于 30 天，用全部可用历史。
2. Codex Memories / rollout summaries；如果数据库或工具可见但无数据，要明确说明为空。
3. Chronicle；只用于发现模式。若无 Chronicle 工具或配置，要明确说明不可用，不要编造。
4. 现有 skills、plugins、custom agents、automations；用来判断复用、扩展或跳过。

如果某类证据不可访问，在最终报告中写清楚“未使用原因”。

## 候选筛选

只把满足以下条件的工作流列为可创建候选：

- 已发生至少两次，或明显高概率复发且重复成本高。
- 输入稳定，例如文章路径、截图、URL、仓库、账号后台、固定目录或固定模板。
- 步骤可重复，不依赖临场灵感。
- 输出或停止条件清楚，例如生成两张封面、写入文章、上传图床、打开画布、完成诊断报告。
- 创建后能明显提升速度、质量、一致性或可靠性。
- 不被现有技能充分覆盖。

边界不清的候选只放入“需要更多证据”，不要创建。

## 审计步骤

1. 列出最近线程，记录日期、标题、用户请求、最终动作。
2. 读取相关线程摘要，不需要把所有工具输出完整展开；只抓工作流、失败点、用户纠正、最终沉淀。
3. 检查 Memories 和 rollout summaries 是否有跨线程模式。
4. 检查 Chronicle 是否启用；若启用，只作为发现线索。
5. 列出现有技能和自动化，特别关注与候选重叠的技能。
6. 形成 compact shortlist。
7. 对每个候选做决策：create、extend existing、automation、subagent suggestion、skip。
8. 只创建高置信缺口。创建前确认不会和已有技能重叠。
9. 最终报告说明创建了什么、跳过什么、还需要什么证据。

## Shortlist 输出格式

使用简洁表格：

| 重复工作流 | 证据和日期 | 频率/信心 | 建议形式 | 判断 |
|---|---|---|---|---|
| 工作流名称 | 线程/记忆/文件证据 | 例如 3 次，高 | extend existing | 已有技能覆盖，只需补规则 |

日期要写具体日期，例如 `2026-06-22`，不要只写“今天”。

## 创建规则

创建 skill 时：

- 名称要窄，避免 `万能助手`、`内容全流程` 这类大而空的名字。
- `description` 写清触发语和边界。
- 只把稳定步骤写入技能；把本次个案、临时链接、敏感账号细节留在证据报告中，不写进技能。
- 不把会话原文大段复制进技能。
- 如果只是已有技能缺规则，优先扩展已有技能。

创建 automation 时：

- 先查现有自动化。
- 能更新已有自动化就不要创建新的。
- 只有明确周期、触发条件和输出格式时才创建。

建议 subagent 时：

- 说明角色边界、输入、输出、何时委托。
- 如果没有持久化自定义子代理工具，只列为建议，不创建假文件。

## 最终报告格式

先给 shortlist，再给结果：

```markdown
**候选清单**
| 重复工作流 | 证据和日期 | 频率/信心 | 建议形式 | 判断 |
|---|---|---|---|---|

**已创建或扩展**
- ...

**刻意跳过**
- ...

**需要更多证据**
- ...

**证据限制**
- ...
```

## 常见判断

- 短视频封面横竖版、安全区、真人融图：如果已有 `cover-generator`，优先扩展它，不新建。
- 文章封面 16:9：如果已有 `article-cover-16x9`，优先复用。
- 文章配图、图床上传、PicGo WebP 坑：若只在一篇文章中出现，先记录或扩展相关配图技能，不急着新建。
- Cowart 画布、标注改图：如果 Cowart 插件技能已存在，优先复用。
- 技能安装、中央同步：如果已有 `install-to-central`，优先使用它。
- 浏览器后台排障：只有多次出现同类平台/权限/扩展阻塞，且步骤稳定，才考虑新建诊断 skill。
